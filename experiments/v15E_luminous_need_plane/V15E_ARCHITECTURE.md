# Neural Glyph v15E — Luminous Need Plane + Charge-Captured Dendrites

## Core rule
v15E keeps v15D's charge-gradient dendrites and adds a package-level optical need surface only for sparse cross-chip communication. There is no consciousness module and no separate thinking software. "Thinking" means the same recurrent fabric keeps an unresolved state active, asks only for the specialist evidence it needs, reintegrates the response, and repeats until its confidence is sufficient.

## Local memory remains physical
A guided-gap firing charges the existing dendrite/HZO electrode. The volatile gap resets and isolates the node, so the charge packet remains temporarily and leaks naturally. Repeated validated use builds charge; repeated charge gradually consolidates HZO polarity. Wrong or unused charge decays.

## LNP — Luminous Need Plane
A small chip-edge emitter field is an internal optical surface, not a human display.
- spatial pixel position identifies a specialist chip;
- three separated route pixels form a 2-of-3 destination signature;
- brightness represents how strongly the current computation needs that specialist;
- eight coarse context pixels can carry a low-dimensional request state;
- the specialist's response returns through the same optical plane and enters the receiving dendrites as another input.

A 2-of-3 signature is used because a single bright pixel produced excessive false wakes in the first v15E run.

## Direct energy activation
Received light creates photocurrent on a tiny need node. That voltage directly controls a shared package-level power gate. There is no per-neuron optical decoder. More received light can produce a longer activation window. Ordinary semantic cells remain 0 MOS; the power gate is shared chip-edge infrastructure.

## Need-based internal dialogue
1. A local route produces a result and confidence/margin.
2. If confidence is high, continue without cross-chip discussion.
3. If confidence is low or the result conflicts with known structure, charge the relevant need pixels.
4. The optical plane activates only the selected specialist chip.
5. The response is reinjected into the same fabric.
6. Repeat only while uncertainty remains.

This is the same AI recursively using its own specialist regions; it is not an external orchestrator.

## Hardware revision request — corrected meaning
Unknown knowledge does NOT request new hardware. A maker-facing revision request is raised only after persistent physical-health evidence such as:
- charge leakage consistently outside the learned envelope;
- repeated timing-margin failure;
- abnormal power/thermal behavior;
- repair-spare exhaustion caused by physical failures;
- repeated read/write margin loss that remains after normal recalibration.

The chip can self-adjust charge, polarity, route preference and repair-branch assignment. It cannot fabricate a new chip. If persistent physical evidence says the hardware itself is poor, it reports the region/symptom to its maker for a future revision.
